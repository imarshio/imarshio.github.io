# 第一部分：Qdrant 与向量检索

## 向量检索 入门（20 题）

### 1. ★ 向量检索解决什么问题？
把文本、图片等变成数值向量，按距离找相近内容，适合表达不同但意思相近的查询。它找到的是模型空间里的相近，不自动等于事实正确，也不能替代精确的编号过滤。

### 2. ★ embedding 是什么？
模型把输入映射为固定维数的表示。入库和查询应使用兼容模型、维度及预处理；两个模型即使都是 1024 维，也不能直接混搜。模型版本要随索引记录。

### 3. 稠密向量和稀疏向量有什么区别？
稠密向量通常每维有值，擅长语义；稀疏向量只有少数非零维，可表达词项及权重，擅长实体名、编号等字面匹配。稀疏不一定就是 BM25，SPLADE 等也是稀疏表示。

### 4. ★ BM25 为什么适合补充语义检索？
它根据词频、逆文档频率、文档长度等给关键词匹配打分。产品型号和错误码可能被语义模型忽略，BM25 能补上；中文分词、同义词和停用词处理会影响结果。

### 5. Qdrant 的 collection、point、payload 是什么？
collection 类似一组统一配置的数据集合；point 包含 ID、向量和 payload；payload 存文档 ID、租户、来源等元数据。它能过滤，但不是关系数据库的外键和事务替代品。

### 6. ★ 余弦、点积、欧氏距离怎么选？
余弦关注方向，点积还受模长影响，欧氏距离看空间距离。先遵循 embedding 模型的训练与使用约定；向量归一化后它们可能产生等价排序，但分数范围和阈值仍有区别。

### 7. top_k 和分数阈值有什么区别？
top_k 控制最多取几条，阈值控制最低匹配程度，两者同时作用可能一条也没有。不同距离和模型的分数不可照抄；阈值应在代表性查询和无答案样本上校准。

### 8. ★ 为什么要分块？
长文档可能超过模型输入长度，整篇一个向量也会稀释局部信息。按标题、段落、表格语义切块，保留文档 ID、章节和原文位置，便于命中后扩展上下文并提供出处。

### 9. chunk overlap 有什么作用？
相邻块共享一点文字，减少信息在边界被切断的损失。重叠越多存储和重复召回越多；不能盲目固定一半重叠，应该结合段落结构和评测选比例。

### 10. ★ ANN 和精确搜索有什么区别？
精确搜索比较全部候选，成本高但可作为召回率基线；ANN 用索引缩小搜索范围，在速度、内存和召回率间取舍。评测 ANN 时，要在同样过滤条件下和精确结果比较。

### 11. HNSW 的基本思路？
构建多层邻近图，高层快速找到大致区域，低层逐步靠近查询点。它通常有较好延迟，但图索引占内存，构建和更新也有成本；不是把数据排序后做二分。

### 12. ★ payload filter 能做什么？
按用户、组织、项目、文档类型等限制候选范围。过滤条件应由服务端可信身份构造；不能接收模型给出的任意 org_id 就当授权通过。常用过滤字段可建 payload 索引。

### 13. upsert 为什么适合文档重试入库？
相同 point ID 再写会更新而不是新增一份，便于幂等重试。ID 应由稳定的文档版本和块标识生成；重切块后块数变少，还要清除旧版本残留，upsert 不会自动替你删旧块。

### 14. ★ 混合检索是什么？（项目）
同时做语义检索与关键词检索，再合并候选。项目文档链路把 dense 和 BM25 sparse 作为两路 Prefetch，交给 Qdrant 的 Fusion.RRF。不是先拿两路原始分数直接相加。

### 15. ★ RRF 是什么？
按名次而非原始分数融合：某条记录每进入一个榜单，就贡献 `1 / (常数 + 名次)`，同一 ID 累加。它避开分数量纲差异，但不利用第一名比第二名强多少的信息。

### 16. ★ rerank 和 embedding 检索有什么区别？
embedding 用预计算表示快速粗选；reranker 同时看查询与候选，通常更慢但可做更细的相关性判断。常见流程是先召回较多，再重排少量；它不能把未召回的文档变出来。

### 17. Recall@K 和 Precision@K 怎么算？
Recall@K 是相关材料被前 K 条找回的比例；Precision@K 是前 K 条中相关材料的比例。必须先定义标注单位是文档还是块；同一篇的五个重复块不能当成五篇相关材料。

### 18. 为什么相似度不能当置信度？
分数反映模型和距离函数下的接近程度，不是答案为真的概率。一个完全错误的问题也会有最近邻；要结合出处、无答案识别和实际标注判断是否足够支持回答。

### 19. Qdrant 和 PostgreSQL 各负责什么？（项目）
向量索引负责召回，PG 保存业务归属、权限等权威状态。索引可能滞后，命中后仍要复核文档是否存在及可读；向量库出现旧 payload 不能让旧授权继续生效。

### 20. ★ 向量检索和知识图谱怎么配合？
向量先定位可能相关的实体或材料，图谱沿明确关系补上下文。回答「谁负责哪个项目」时图遍历有价值；只要找一段相似原文时，向量检索更直接，没必要为所有文本强建图。

## 向量检索 中等（20 题）

### 1. ★ HNSW 的 M 和 ef 分别控制什么？
M 影响每个节点连接数，通常越大图越占内存；ef_construct 影响建图质量和耗时；查询 ef 影响搜索范围、召回率和延迟。先固定数据集画召回率与 P95 曲线，再选参数。

### 2. payload 索引为什么能提速？
索引帮助估计和定位满足条件的点，避免过滤时反复检查大量 payload。不是每个字段都要建；高频租户/项目/状态过滤值得优先考虑，同时记录索引构建和更新成本。

### 3. ★ 先过滤还是检索后过滤？
检索时过滤能避免 top_k 被无权数据占满；检索后复核能处理索引过时。两者都要：先带可信过滤召回，再按权威源复核，必要时有上限地补召回，不能越权凑满 K。

### 4. 多租户放一个 collection 还是拆开？
共享集合便于统一运维，小租户成本低，但过滤和配额必须可靠；独立集合隔离强，集合与索引管理成本高。按租户大小和合规边界选择，可让大租户独立，小租户共享。

### 5. ★ 同一个 collection 能存多个向量吗？（项目）
可以用 named vectors 为不同表示配置名字和维度。项目图节点用 name-embedding 和 summary-embedding 两个名字，各自查询；它们不是简单拼接成一条长向量再算距离。

### 6. ★ 为什么不能把 BM25 分数加到余弦分数？
它们范围和分布不同，直接相加会让量纲较大的一路支配结果。可用 RRF，或在标注集上学习归一化权重；调整权重必须用固定查询集验证，不能只看一个示例。

### 7. 项目的两种 RRF 有什么区别？（项目）
文档 dense/BM25 在 Qdrant 服务端融合；图节点 name/summary 在 Python 里融合，`_RRF_K=60`。这个 60 是项目图融合的常数，不能说成所有 Qdrant 服务版本的默认值。

### 8. 召回 K 和最终 K 为什么分开？
最终只展示 5 条，不代表只需召回 5 条。重排、去重、权限复核都会损失候选；可以先取几十条再筛成 5 条，但要给成本与延迟设上限，并评测新增候选是否真正提高覆盖。

### 9. ★ 如何做文档更新的一致性？
PG 记录文档版本和入库状态，索引按版本写入并校验；新版本就绪后切换可见版本，再清理旧块。通过 outbox/重试/对账补偿跨库窗口，不把 PG 和 Qdrant 当成一个原子事务。

### 10. 怎么生成稳定的 point ID？
可由租户、文档 ID、版本、块标识生成 UUID，保持重试相同 ID。不要只用段落内容哈希，否则不同文档可能合并掉权限和出处；内容去重和业务身份需要分别设计。

### 11. 小块命中后为什么要扩展父块？
小块有利于定位，但单独一句可能缺主语、时间或表头。命中后按父章节取适度邻文，把来源位置一并带回；扩展仍需做权限检查并受上下文预算限制。

### 12. ★ MMR 解决什么问题？
在相关性与结果多样性间取舍，减少前几条都是同一段话。可在候选上迭代选取与已选集合不太重复的条目；不适合把精确查编号的结果强行多样化。

### 13. 查询改写怎样避免跑偏？
保留原始查询作为一路，改写只补同义表达、上下文缺失信息。对型号、日期、否定词做保真检查；各路带上查询版本便于对比，不能把模型猜测当成用户给定条件。

### 14. 向量缓存的键包含什么？
模型及版本、输入预处理版本、归一化后的文本哈希。结果缓存还需权限范围、文档索引版本和检索参数；只按问题缓存可能把 A 用户可见内容返回给 B 用户。

### 15. 量化怎么省资源？
将高精度向量近似压缩成更少位数，减少内存或计算；代价是距离误差和潜在召回下降。可扩大候选后用原始向量复算，量化前后都要在相同过滤条件下评测。

### 16. on_disk 就是不占内存吗？
不是。向量、索引和 payload 的磁盘配置分别影响工作集，操作系统页缓存仍占内存，随机读还受磁盘延迟影响。容量估算要分别列原始向量、图结构、payload 和缓存。

### 17. ★ 入库失败怎么重试？
分清解析、embedding、索引写入和状态回写阶段；以文档版本/分块 ID 幂等重试。不要失败后整个文档无限重跑；记录失败块、原因、次数和下次时间，区分限流与不可解析数据。

### 18. rerank 超时怎么降级？
保留粗排结果，给重排设置独立 deadline 和候选上限；超时按策略返回粗排并记录降级原因。权限复核属于必需步骤，不能和 rerank 一起跳过；记录质量与耗时损失。

### 19. 分页为什么不能反复取 top_k 后切片？
检索期间数据和近似排序可能变化，重复切片会漏或重；大 offset 还可能扩大预取成本。浏览全量数据用 scroll，搜索分页用服务支持的方式或短期冻结候选，明确一致性语义。

### 20. ★ 怎么建一个检索评测集？
覆盖同义表达、型号、否定、跨段、无答案、多租户和权限撤回。记录预期文档/片段及可见范围，同时看召回、排序、无答案误报、P95 和成本；保留一组不用于调参的样本。

## 向量检索 高难（20 题）

### 1. ★ 一亿条向量怎么估容量？
先算 `条数×维度×每维字节`，例如一亿×1024×4 约 409.6GB，仅是原始向量十进制大小。再加副本、HNSW、payload、WAL、迁移双份和磁盘余量；按实际样本测索引膨胀率。

### 2. ★ P99 从 100ms 涨到 2s 怎么查？
拆 embedding、过滤召回、网络、rerank、PG 复核耗时。看并发、磁盘缺页、索引构建和租户热点；用同一批 query 比较冷/热缓存。先找到慢段，再改索引参数或扩容。

### 3. ★ 过滤越严格反而越慢？
候选子集稀疏时，图搜索可能难以找到足够满足条件的点。检查 payload 索引、过滤选择性和实际执行路径；比较精确扫描小子集、增大搜索范围及租户分片，不能只说提高 ef。

### 4. embedding 升级怎么不停服？
新建版本索引，历史回填与增量双写并行，固定评测集比较新旧效果；灰度切读，留旧索引可回退。换模型时查询向量与索引必须一起切，不能只换查询端然后混用旧空间。

### 5. ★ 租户被移除成员后还搜到片段？（项目）
payload 可能滞后，缓存也可能含旧结果。按当前可信身份重新解析 read scope，命中后回 PG 复核文档归属与权限，无 original_id 的片段不返回；缓存键和失效机制也要跟着改。

### 6. 重排效果好但总延迟超标怎么办？
量化重排收益集中在哪类查询，再限制候选、批处理、分层路由和超时降级。比较最终答案质量与成本，避免为了平均 NDCG 提升，让精确查询也多等一次昂贵模型调用。

### 7. ★ 索引写成功但 PG 状态回写失败？
不要简单删掉向量，因为提交结果可能未知。用版本/幂等键重查索引和业务状态，再安全地完成或标记孤儿；后台对账清理。将「写入成功」与「可供查询」分成明确状态。

### 8. 删除 PG 文档却漏删向量怎么办？
先让业务删除状态立即参与权限复核，防止索引残留泄露；再可靠投递索引删除并对账。保留 tombstone 或删除版本，避免旧重试又写回；只发一次异步删除不够。

### 9. 热租户把整个集群拖慢怎么处理？
按租户看 QPS、候选量、重排 token 和尾延迟，再限并发与预算；大租户可独立分片/集合或实例。扩容前先处理无界查询和重试，不然只是把瓶颈推到 embedding 服务。

### 10. 多副本和读写一致性怎么选？
副本提高可用性和读能力，但更新传播、写确认和读一致性有取舍，具体能力按版本确认。权限撤回不依赖向量副本立刻同步，仍回权威源校验；用故障演练测恢复时的旧读窗口。

### 11. ★ ANN recall 很高但用户仍说找不到？
ANN recall 是相对精确向量邻居的接近程度，未必是业务相关性。检查解析漏表、切块、模型领域适配、权限误过滤和评测标注；分别测检索相关性与 ANN 算法召回，别混成一个指标。

### 12. 中英混合、代码、图片怎么统一检索？
先确认模型覆盖输入类型与语种，必要时不同表示分路召回再融合。代码保留符号和路径，图片带 OCR 与版面信息；不能把所有模态都当作截断后的普通中文句子。

### 13. 用户问题含多个约束，检索只命中一半怎么办？
把可精确判断的日期、对象、权限转成结构化过滤，语义部分可分解召回再验证约束。区分「材料分别相关」和「同一证据同时满足」；若证据不足，明确缺失条件。

### 14. ★ 怎么降低重复块挤占上下文？
按文档/父章节聚合，近重复检测后保留最有信息量的块，控制单文档份额；为被删块保留出处映射。用多样性和答案证据覆盖衡量，不只看返回条数有没有达到 K。

### 15. RRF 常数怎么调？
较小常数更重视榜首差距，较大常数让不同名次贡献更接近。固定各路候选深度，比较 NDCG、覆盖和无答案误报；常数与候选量应联合验证，不能因为图代码用 60 就所有链路照搬。

### 16. 索引重建期间怎样控制资源？
后台限速并预留磁盘与峰值内存，观察写延迟和查询尾延迟；必要时分片滚动重建。提前演练失败重试和回退，避免旧索引未清、新索引又重来导致容量翻倍后耗尽。

### 17. ★ 如何验证备份真的可恢复？
在隔离的本机实例恢复 snapshot，并核对 collection 配置、点数、payload 索引及代表性检索。再从 PG/原文补齐快照之后的增量；向量快照不包含外部原始文件和业务权限真相。

### 18. 检索服务超时能直接让模型凭知识回答吗？
按业务约定区分知识问答与必须有内部证据的问题。内部制度、合同数字等应返回证据暂不可用或降级检索；若允许通用回答，清楚说明来源边界，不能编内部出处。

### 19. 多路查询导致成本爆炸怎么办？
给查询改写数、每路候选、重排 token、总 deadline 设预算；简单查询走短路径，复杂查询按需扩展。监控每次多路的边际收益与失败率，避免递归改写和无界补召回。

### 20. ★ 面试问「你们怎么证明 RAG 有用」？
拿固定样本比较纯模型、关键词、向量、混合、混合加重排五条路径；看答案证据支持率、无答案拒答、延迟和费用。项目实现能讲源码；没有真实业务指标就讲评测方法，不编提升百分比。

# 第二部分：Neo4j 与知识图谱

## 知识图谱 入门（20 题）

### 1. ★ 属性图是什么？
用节点表示实体，关系表示联系，节点和关系都可带属性。Neo4j 属于属性图；标签用来归类节点。它适合有关系遍历需求的数据，不是把所有业务表都换成圆圈和箭头。

### 2. 节点、标签、关系类型分别是什么？
例如「张三」是节点，Person 是标签，WORKS_ON 是关系类型。节点可有多个标签；关系有方向和类型，也能存角色、有效期。业务 ID 应自己维护，别依赖内部存储 ID 长期稳定。

### 3. ★ Cypher 和 SQL 有什么不同？
Cypher 用图模式表达节点和关系匹配，SQL 用表与连接表达关系。两者都需要索引、约束和执行计划；图查询写着短，不代表执行一定快或没有笛卡尔积。

### 4. MATCH 和 WHERE 怎么用？
MATCH 描述要找的模式，WHERE 给匹配加条件。先用带标签和索引字段定位起点，再展开关系，通常比从所有节点出发扫描便宜。租户条件同样要写进受控查询。

### 5. CREATE 和 MERGE 的区别？
CREATE 总是新建指定模式；MERGE 尝试匹配整个模式，不匹配才创建。MERGE 不自动猜哪个字段是身份，应该用稳定 ID 匹配，把会变的摘要等属性放进 SET。

### 6. ★ MERGE 能保证并发不重复吗？
不能单独保证。并发下还需要对业务唯一键建立唯一约束，遇到冲突按策略重试。关系身份也要设计清楚，避免一次模式 MERGE 因部分不匹配而创建多余节点。

### 7. SET、REMOVE、DELETE 有什么区别？
SET 更新属性或标签；REMOVE 移除属性或标签；DELETE 删除节点或关系。节点还有关系时普通 DELETE 会失败；DETACH DELETE 会连关系一起删，范围必须严格限制。

### 8. ★ 为什么要用查询参数？
参数绑定避免把用户值拼进 Cypher，便于复用计划。动态标签/类型等结构部分要按服务版本能力处理，无法参数化时做白名单映射；参数化不代替权限检查和查询限额。

### 9. 什么是度数？
节点连接的关系数量。少数高频实体可能成为超级节点，遍历时造成候选爆炸；「公司」「所有文档」这类泛化节点尤其要控制扩展范围，不能只看全图平均度。

### 10. ★ 一跳和多跳查询是什么？
一跳沿一个关系到邻居，多跳经过多个关系。跳数不是业务可信度；两个项目都连到同一部门，不等于项目之间存在合作。返回路径时要解释每条边的含义和出处。

### 11. OPTIONAL MATCH 有什么用？
类似可选关联，模式未匹配时保留原行，相应值为 null。WHERE 的归属会影响结果；把条件放错位置可能把本想保留的行过滤掉，需要用「无关系」样本验证。

### 12. UNWIND 是什么？
把列表展开成多行，适合批量写入或处理参数列表。展开会放大行数；两个列表连续 UNWIND 可能形成乘积，批量写要控制批次并用稳定键保持幂等。

### 13. ★ 知识图谱比向量检索强在哪里？
明确的实体、类型和关系支持可解释的结构查询，比如某人负责的项目及其依赖。前提是抽取和实体对齐足够可靠；图谱不是天然事实库，错误关系会被查询稳定放大。

### 14. 实体消歧是什么？
区分同名实体是不是同一个，例如两位「王伟」不能仅凭名字合并。结合组织、外部 ID、时间、上下文判断，保留候选和证据；误合并通常比暂时分成两个节点更难修。

### 15. 本体或 schema 有什么作用？
限定实体类型、关系类型、必要属性和允许的起终点，减少「负责人」「负责者」等散乱表达。它应随业务演进并有版本；过度僵硬会丢信息，完全自由则难以查询与治理。

### 16. ★ 事实和推断为什么分开？
原文明确写出的关系，与模型根据线索猜出的关系可信程度不同。分别记录层级、来源和置信信息，回答时说明推断；不能让多跳组合自动升级成原始材料明确陈述的事实。

### 17. 为什么边也要记录来源？
同一对实体可能在不同时间、材料里有不同关系。记录来源文档、片段、提取版本和时间，有利于追溯、重抽和撤销；只存一句关系文本，之后无法解释为何得到这个结论。

### 18. ★ 项目图谱和向量库怎么分工？（项目）
Neo4j 存结构关系，Qdrant 存节点名称/摘要表示帮助语义定位。图节点 ID 用来串起两边；两库更新不是天然原子，要考虑索引残留、缺失和重试。

### 19. 图谱的读取和修改由谁做？（项目）
当前图只读工具向主 Agent 开放，三个图写工具限制给 ariadne。不要照旧文档说「读图也必须委派」；子 Agent 合并仍是计划，不改变当前工具注册事实。

### 20. Neo4j 可以替代业务 PG 吗？
能存属性不等于适合所有业务。订单、成员权限和事务型状态放关系数据库更自然；复杂关系遍历放图谱。跨库边界要明确，避免两个库都声称自己是同一权限事实的最终来源。

## 知识图谱 中等（20 题）

### 1. ★ 图索引和唯一约束怎么选？
索引帮助按标签及属性定位节点；唯一约束保证业务键不重复，并有相应索引支持。多租户实体可用租户加业务键作为组合身份；具体约束能力按 Neo4j 版本和版本类型核对。

### 2. MERGE 为什么只放身份字段？
把名称、摘要等可变属性都写进 MERGE，任一属性变化就可能匹配不到旧节点。先按稳定 ID MERGE，再 SET 可变属性；更新空字段时明确是删除、保持旧值还是写入空字符串。

### 3. ★ 怎么批量写图？
用参数列表加 UNWIND，每批一个短事务，控制批次和并发。先建所需索引/唯一约束再灌数据；重试整个事务时必须幂等，事务回调里别顺带调用会重复扣费的外部接口。

### 4. 如何避免无界遍历？
给起点、关系类型、方向、最大跳数和返回量设限制。只在末尾 LIMIT 不能保证中间枚举少；高阶路径查询还要设超时，必要时按业务限定路径或预聚合。

### 5. ★ EXPLAIN 和 PROFILE 有什么区别？
EXPLAIN 展示计划而不真正执行；PROFILE 执行并给出实际行数、DB hits 等。检查起点是否走索引、行数在哪个算子激增；写查询的 PROFILE 也会写数据，不能当只读分析。

### 6. 为什么会出现笛卡尔积？
独立模式没有关联约束，例如分别匹配全体人员和项目后才处理。检查变量是否真正连起来，先缩小起点再匹配；看计划中的估计/实际行数，不因返回只十条就认为代价小。

### 7. DISTINCT 为什么不能随便加？
它能消除多路径造成的重复结果，但需要额外去重内存与计算，也可能掩盖错误模式。先确认返回单位是节点、边还是路径，再在正确层级去重，不把不同来源关系误合并。

### 8. ★ 实体对齐怎么做得稳？
先用租户内外部 ID、规范化名称等确定性规则，再用向量召回候选，最后结合类型和上下文判别。低把握保留待核对；记录合并历史和别名，支持拆回，别让模型一句话直接合并。

### 9. 图里如何表示时间变化？
区分业务有效时间和系统记录时间；对「某人负责某项目」可存有效区间或单独关系事件。查询要明确问当前还是历史，不要覆盖旧属性后还声称可以回答过去的状态。

### 10. 图谱更正为什么适合软废弃？
废弃能保留审计、来源和历史回答解释，再在默认查询排除。物理删除更省存储但难追溯；对法规或业务要求必须删除的情况，还需同步清理向量索引、缓存和原始材料。

### 11. ★ 文档更新后怎么重抽关系？
给每次抽取带文档版本和任务 ID，先生成新证据，验证后替换该来源的贡献。不能直接删节点所有边，因为还有别的材料也支持这些关系；实体身份与证据生命周期要分开。

### 12. 多来源支持同一个关系怎么存？
可把关系断言/证据建成独立记录，汇总视图再返回实体之间的关系。这样撤回一份材料不必删除其他支持；权威程度、时间和来源独立保存，不只把置信分数简单相加。

### 13. ★ 图查询怎么做租户隔离？
从可信 scope 限定起点，每一步扩展的节点与关系也符合允许范围；尤其防跨租户的脏边。结构化查询模板统一注入条件，结果再复核，不能只在返回的第一个节点检查组织。

### 14. Text2Cypher 的危险在哪里？
模型可能生成写语句、无界遍历或遗漏权限。应使用只读数据库身份、允许的查询结构、硬超时和结果上限；参数值来自用户但 scope 来自服务端。提示词写「只读」不形成权限边界。

### 15. 图向量命中后怎么扩展？
先核对命中节点是否仍存在、可读，再按关系白名单做少量跳数扩展，保留路径和出处。按上下文预算截断并说明未展开部分；不能把所有邻居全部塞进 prompt。

### 16. 图查询结果怎么排序？
按问题选择时间、业务权重或相关性，不默认内部 ID 排序。多条路径可根据证据质量和长度排序，但最短不一定最可信；稳定分页还要加唯一键作为并列排序条件。

### 17. ★ 超级节点怎么建模？
把无差别聚合关系按时间、业务域分组，查询先筛子类；高频统计可预计算。不随意复制实体来消除度数，否则身份与更新会漂移；先测真实遍历模式再改模型。

### 18. 图事务失败怎么重试？
对驱动判断为可重试的瞬时错误进行有限退避，业务唯一键保证幂等；语法和授权错误不能盲重试。驱动事务回调可能被多次执行，外部副作用应放事务外并单独幂等。

### 19. 怎么测试抽取效果？
人工标注实体、关系、来源位置和否定/时间范围，分别看精确率、召回率、误合并、无来源断言。最终再测业务问答的证据支持率，不能用「节点变多」证明知识质量提高。

### 20. ★ 图 schema 改版怎么兼容？
新旧关系类型并存过渡，读取层明确兼容规则，分批回填并校验数量和典型路径。切换后观察旧查询命中情况再清理；prompt、本体校验、索引与图查询模板要一起升级。

## 知识图谱 高难（20 题）

### 1. ★ 两个来源对负责人说法冲突怎么答？
同时保存来源、有效时间和权威级别，先判断是时序变化还是同一时点冲突。返回有出处的差异或请求确认，不能简单选最新写入或最高模型分数；业务裁决后留更正历史。

### 2. ★ 文档权限撤回后，图关系会泄密吗？
会，摘要和路径也可能暴露原文事实。按证据来源维护可见范围，查询阶段及输出阶段都过滤；一个关系仍被公开来源支持时可保留该公开证据，不能把私有来源一起带出。

### 3. PG、Neo4j、Qdrant 三库怎么保持一致？
权威业务事件带版本写入 outbox，各存储消费时幂等更新并记录版本；读时校验业务有效性，后台对账补偿。跨库不强装成一笔 ACID 事务，要定义短暂不一致时可接受与必须拒绝的行为。

### 4. ★ 图查询突然占满 CPU 怎么查？
从慢查询和参数复现，PROFILE 看实际展开量、全图扫描、路径枚举和去重。先终止异常查询、限并发，再限制起点和路径；不要先给所有关系建索引却不看瓶颈。

### 5. 千万节点做全图多跳为什么危险？
候选量随分支数和跳数快速放大，路径数还可能远多于节点数。先把业务问题改写成有限关系模式，必要时离线预计算；「最多返回 20 条」无法证明中间过程便宜。

### 6. 如何安全合并两个实体？
先核对 scope、类型和证据，事务内重连边并处理重复断言，保留旧 ID 到新 ID 的映射。向量索引异步更新并对账；设计反向拆分需要的记录，否则一次误合并很难恢复。

### 7. ★ 图查询有路径但答案不成立？
路径连通只说明存了这些关系，关系组合是否能推出结论还需业务规则。检查方向、时间交集、否定和关系含义；展示证据链，并把模型补出的推断与原始事实区分。

### 8. 同一个名字在多个组织都存在怎么办？
身份键带 scope，先在有权范围内做候选检索；跨组织同名不自动合并。确有全局身份时另外维护受控映射和授权规则，避免查询内部图时无意返回其他组织的存在信息。

### 9. 图抽取任务重试导致关系越来越多？
检查关系身份是否包含不断变化的属性、是否缺少唯一业务键，以及每次抽取是否清理同来源旧版本。以来源断言 ID/抽取版本做幂等，做重复关系检测，不能定期全库去重代替修写入逻辑。

### 10. ★ LLM 生成了合法但昂贵的只读查询？
只读不代表安全。实施跳数、起点规模、允许算子、超时、行数及并发预算，复杂模式转受控工具。分析无害小样本与真实图规模下的代价，不能仅靠解析成功就执行。

### 11. 怎么设计图谱灾难恢复？
备份图数据、schema、本体和抽取版本，保存重建所需原文与事件水位。恢复后检查约束、代表性路径、权限隔离及向量映射；重放增量前按版本防止旧事件覆盖新修正。

### 12. Neo4j page cache 命中低怎么办？
先看工作集、内存预算和查询随机访问，区分堆、page cache 与 OS 缓存。优化起点和返回属性，确认磁盘延迟，再调缓存或扩容；不能把所有 RAM 分给堆导致页缓存饥饿。

### 13. ★ 多人同时改同一关系怎么防覆盖？
更新附带版本或预期旧值，事务内检查影响结果；冲突时重读给出差异。对聚合边要小心不同来源贡献被整体 SET 覆盖，尽量按独立证据修改，保留审计与操作者。

### 14. 图模型演进后历史问答还能解释吗？
答案记录证据 ID、图/抽取版本和查询时点；实体重定向保留历史映射。只保留最终自然语言答案无法追查旧推断；对真正需要复现的场景还需保留当时证据快照。

### 15. 为什么不让主 Agent 直接改图？（项目）
当前共享图写入权限集中给 ariadne，控制领域规则和修改入口。仍须在写工具执行时验证 scope、身份和目标，委派本身不等于授权；只读开放不代表写入边界也已开放。

### 16. 多来源关系的置信度能直接累加吗？
不能，多篇转载可能只有同一个原始来源，模型错误也可能相关。先做来源去重并区分独立证据、权威性和冲突；若输出概率需要校准，别把任意加权分数叫正确概率。

### 17. ★ 图谱删掉原文后还保留摘要吗？
先按数据保留规则决定，而不是为了检索效果默认保留。摘要可能同样含敏感信息；删除事件应覆盖节点、断言、向量、缓存和产物。合法审计保留需限定权限和期限。

### 18. GraphRAG 比普通 RAG 一定更好吗？
不是。结构关系密集、需要多跳的问题可能受益；单段原文查找可能增加抽取错误和延迟。用同一题集比较增益与维护成本，只有明确收益再扩图，不把架构复杂度当技术成果。

### 19. 图写入中途失败，哪些地方必须原子？
单个图事务内的节点与关系修改要么一起成功要么回滚；外部 embedding 和 PG 状态另有补偿。不要在 Neo4j 长事务里等模型；先得到候选再用短事务提交，失败能按抽取 ID 重试。

### 20. ★ 怎么向面试官讲项目图谱的现状和后续？
