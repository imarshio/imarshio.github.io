# 第一部分：React

## React 入门（20 题）

### 1. ★ React 解决什么问题？
用组件和状态声明界面，让视图随数据变化。它主要负责 UI，不自带完整后端、路由或权限系统；项目再用 Next 做应用组织，用 Redux 等管理跨组件状态。

### 2. JSX 是 HTML 吗？
不是，是 JavaScript 语法扩展，编译成创建 React 元素的调用。可以在花括号里放表达式，组件名首字母大写；样式、className 和事件属性遵循 React/JS 的约定。

### 3. ★ props 和 state 的区别？
props 是上层传入的数据，组件不应直接修改；state 是组件拥有的状态，更新会请求重新渲染。先确定数据归谁管，避免父子各存一份同样数据而不同步。

### 4. useState 的 setter 为什么不是马上改变量？
当前渲染拿到的是一次状态快照，setter 请求后续渲染。依赖旧值更新时用函数式写法 `setCount(c => c + 1)`，避免同一事件里多次使用旧快照丢更新。

### 5. ★ 为什么不能直接改 state 对象？
React 依赖引用和更新队列判断变化。原地修改再传同一个引用可能不触发期望更新，也破坏旧快照；用新对象/数组表达改动。Redux Toolkit 的 reducer 可借助 Immer 写看似可变的语法。

### 6. 列表为什么要 key？
key 帮 React 在同一父级内识别项目身份，维持正确的组件状态。优先业务稳定 ID；可插入、排序的列表用数组下标容易让输入框状态跟错行，随机 key 会反复重建。

### 7. ★ 什么是受控表单？
输入值由 React state 控制，onChange 更新状态；非受控表单由 DOM 管理，可用 ref 读取。受控方便校验联动，但大表单要控制更新范围，别让每次按键重渲染整页。

### 8. 事件处理和普通 DOM 有什么不同？
传函数引用，例如 onClick={handleClick}，不要在渲染时直接调用。React 封装事件传播；阻止冒泡与阻止默认行为是两件事。旧版 SyntheticEvent 池化的说法不能直接套到现代 React Web。

### 9. ★ useEffect 用来做什么？
在提交后与外部系统同步，例如订阅、网络连接、第三方控件。由用户点击触发的操作通常放事件处理器；可直接从 props/state 算出的值通常在渲染时计算，不必再存一份状态。

### 10. Effect 的依赖数组怎么写？
包含 Effect 使用的响应式值，按依赖变化重新同步。漏依赖容易读到旧值；依赖对象每次新建又会反复执行。先调整代码结构和稳定输入，别靠关闭 lint 掩盖问题。

### 11. ★ Effect cleanup 什么时候执行？
下一次同步前清理旧 Effect，组件卸载时也清理；开发 StrictMode 还会额外检查 setup/cleanup。取消订阅、定时器、请求和连接，避免重复监听与卸载后继续处理旧结果。

### 12. useRef 和 useState 的区别？
ref 保存跨渲染的可变值或 DOM 引用，修改 current 不触发渲染；state 用于影响界面的数据。不要把需要实时展示的加载状态只放 ref，也别在渲染里随意读写 ref 代替状态。

### 13. ★ Hooks 为什么不能随便写在条件里？
useState、useEffect 等依赖稳定调用顺序来关联状态，应在组件或自定义 Hook 顶层调用。React 19 的 use(resource) 有条件调用等例外，但不能因此把所有 Hook 都放进条件或循环。

### 14. 自定义 Hook 是共享状态吗？
它复用有状态逻辑，每次调用通常拥有独立状态，不自动共享数据。真正共享需要把状态提升到公共祖先，或通过 Context、外部 store、查询缓存等提供同一数据源。

### 15. 条件渲染有哪些坑？
可以用 if、三元表达式或短路，但 `0 && <List />` 会显示 0。加载、空、错误和成功应区分；权限未确定时不要先展示敏感数据再隐藏。

### 16. ★ 状态提升是什么？
多个组件需要同步同一数据时，把数据放到最近的共同拥有者，再通过 props/回调传递。不是所有状态都要放全局；弹窗开关、未提交输入等局部状态尽量靠近使用处。

### 17. Context 和 Redux 怎么选？
Context 适合传主题、身份等跨层数据，本身不是精细订阅和异步数据管理方案。Redux 适合复杂共享状态和可追踪更新；也可让服务端数据交给专门查询缓存，避免全塞进一个 store。

### 18. CSS Modules 和普通 CSS 有何区别？
模块化类名减少全局冲突，适合组件样式；普通 CSS 用于全局基础规则。项目用 SCSS Modules 和 antd，新增组件优先遵循已有 token 与样式约定，而不是另起一套配色。

### 19. ★ 什么会触发组件渲染？
自身状态、父组件渲染、消费的 Context 或外部订阅变化等。渲染是计算 UI，提交才改 DOM；一次渲染不等于真实 DOM 全部重建，优化前先看实际提交与耗时。

### 20. React 19 值得了解什么？
Actions、useActionState、useOptimistic、use(resource) 等改善异步交互；函数组件也可按新约定接收 ref。先确认框架集成与使用条件，不能把新 API 当作无需处理错误、并发或授权的捷径。

## React 中等（20 题）

### 1. ★ useMemo 和 useCallback 的区别？
useMemo 缓存计算结果，useCallback 缓存函数引用。只有昂贵计算或下游依赖稳定引用时才有收益；依赖变化照样重算。它们是性能工具，不应成为业务正确性所依赖的持久存储。

### 2. React.memo 什么时候有效？
父渲染而 props 引用未变时可跳过子渲染；自身 state 和消费的 Context 变化仍能触发更新。每次传新对象、内联函数会削弱收益，先缩小 props 和订阅范围再评估。

### 3. ★ stale closure 是什么？
定时器、回调保存了某次渲染里的旧 state/props，后续调用读到旧快照。按场景使用正确依赖、函数式更新或 ref 读取最新值；不应靠把依赖数组清空来「只跑一次」。

### 4. 请求 A 后发先至，怎么避免覆盖 B？
切换条件时取消旧请求，或给请求加递增序号，只接纳当前序号结果。取消是减少浪费，结果版本检查是防旧数据覆盖；缓存库也要把完整查询条件放进 key。

### 5. ★ useReducer 适合什么情况？
状态有多个相关字段和明确转移规则时，用 action 描述事件、reducer 纯计算新状态。它不自动变成全局 store，也不该在 reducer 里请求网络或读不确定的外部值。

### 6. Redux Toolkit 的数据流是什么？（项目）
组件触发 action/thunk，异步请求走 services，slice 处理状态，selector 供组件读取。项目的分层不允许 store 反向依赖组件；共享错误处理也有既定 middleware，按入口约定使用。

### 7. ★ selector 为什么要精确？（项目）
若订阅整个工作区大对象，任一流式字段变化可能让大量组件重渲染。只选实际使用的字段，派生数据用稳定 memoized selector；不要为了少写几行把整片状态传给每个列表项。

### 8. Immer 为什么允许写 state.x = y？
它提供草稿代理，记录修改后产生结构共享的新状态，不是直接改原始 Redux state。不要同时修改 draft 又返回另一份不相关结果；草稿也不该逃逸到异步回调里使用。

### 9. ★ 批处理会改变什么？
多个状态更新可合并成一次渲染，减少中间提交。它不改变闭包快照语义；依赖旧值仍用 updater。需要在 DOM 更新后测量时遵循对应时机，不要随便用 flushSync 强迫每次同步提交。

### 10. useLayoutEffect 和 useEffect 怎么选？
布局测量并在浏览器绘制前调整时可用 useLayoutEffect，但它阻塞绘制，重逻辑会卡屏。一般外部同步用 useEffect；服务端没有可测布局，首次渲染需有稳定占位。

### 11. ★ Suspense 能处理所有请求吗？
不能自动接管普通 Effect 里发起的 fetch。它对接框架或支持 Suspense 的数据资源、lazy 组件，等待时展示 fallback；错误仍需错误边界，缓存与请求稳定性由资源层负责。

### 12. Error Boundary 能捕获哪些错误？
主要捕获后代渲染等 React 生命周期错误；普通事件回调、任意异步 promise 拒绝不自动由它接管。分别做好局部异步错误处理与渲染兜底，提供重试和可追踪的错误信息。

### 13. ★ 长列表如何优化？
先分页和缩小订阅，再用虚拟列表只渲染可见区；动态高度要测量与缓存。注意键盘定位、屏幕阅读器、搜索定位和滚动恢复，不能只以 DOM 变少判断体验完成。

### 14. React 里怎么接 SSE？
Effect/独立连接层管理生命周期，收到事件写入有序模型，再按帧或短时间窗口批量更新 UI。断开需取消读取和清理定时器；支持 POST/自定义头时可用 fetch 流，不强套原生 EventSource。

### 15. 防抖和节流有什么区别？
防抖等输入停止一段时间再执行，适合搜索建议；节流限制执行频率，适合滚动、流式刷新。都要清理尾部定时器，保存必要的最后一次更新，不能让结束事件被节流吞掉。

### 16. ★ 乐观更新失败怎么回滚？
记录本次 mutation 的版本或临时 ID，先局部展示，成功用服务端结果对齐，失败只撤回本次影响。并发编辑不能整块覆盖回旧快照，否则会抹掉之后的成功操作。

### 17. 为什么不把所有派生值都存 state？
同一数据出现多份来源容易不一致，还要 Effect 维护同步。筛选结果、总数等能从已有状态纯计算时直接算；昂贵时 memoize。只有需要独立编辑或保留历史快照时才另存。

### 18. 组件拆分的依据是什么？
按职责、状态所有权、更新频率和复用边界拆，而不是只按代码行数。把高频流式区域与静态侧栏分开，减少更新波及；仍保持数据流清楚，避免为了拆小大量跨层传递。

### 19. ★ 如何测试一个异步 Hook？
验证加载、成功、失败、取消及竞态行为，mock 网络边界而非内部 setter。通过用户可观察结果断言；对请求 A/B 乱序、卸载和依赖切换专门覆盖，不能只测最终成功一次。

### 20. useSyncExternalStore 有什么用？
为 React 订阅外部可变数据源提供一致快照协议，框架状态库通常已处理。subscribe 要可清理，getSnapshot 结果要稳定；SSR 还要提供匹配的服务端快照，避免首次水合不一致。

## React 高难（20 题）

### 1. ★ token 一来就 setState，页面卡顿怎么办？
先测事件频率、每次提交耗时和 Markdown 重解析。连接层缓冲，按帧批量追加，终态立即 flush；只更新目标卡片，长内容分块渲染。优化后同时看字延迟和滚动流畅度。

### 2. 重新连接后消息重复怎么处理？
先确认协议是全量重放还是从游标续传；全量重放应清空本次视图再重建，增量续传按事件 ID 去重。不能一边保留全部文本一边重放从头追加，否则正常协议也会显示重复。

### 3. ★ 用户切会话后，旧流写进新会话？
连接与目标 card/session ID 绑定，切换时取消旧 reader，事件落库前再核对运行版本。按目标 ID 更新归一化状态，别让闭包读取「当前选中会话」决定事件归属。

### 4. 组件 key 改了为什么输入丢失？
key 变化意味着身份变化，React 可能卸载旧组件并创建新组件，局部输入也重置。排查是否使用时间戳/随机数或位置 key；需要保留草稿时按稳定业务 ID 存到合适层。

### 5. ★ StrictMode 导致重复请求，是 React 的 bug 吗？
开发额外执行用于发现不纯渲染和缺少清理。查询可取消或复用缓存；购买、发通知等副作用放明确事件并带幂等键。别简单关 StrictMode，也别用 ref 掩盖漏掉的 cleanup。

### 6. 大型 Context 导致全站重渲染怎么改？
拆不同更新频率的 Context，稳定 Provider value，把高频状态放支持 selector 的 store。先确认真正慢的组件；单纯给每层包 memo，仍可能被 Context 更新穿透。

### 7. useMemo 写了为什么仍慢？
依赖每次变化、真正瓶颈在 DOM/布局、缓存开销过大或父级频繁订阅都可能发生。用 Profiler 和浏览器 Performance 定位渲染、提交与布局，再决定减少工作还是缓存计算。

### 8. ★ 前端取消请求等于后台停止 Agent 吗？
不等于。AbortController 主要终止客户端等待/传输；后台任务可能继续。需要调用业务停止接口并处理确认状态，UI 区分连接断开、取消请求和运行已停止，不能直接显示已成功停止。

### 9. 多次点击提交怎样防重复副作用？
按钮禁用只是体验层，多个标签页和网络重试仍会重复。客户端为一次业务操作使用稳定幂等键，服务端原子领取或唯一约束；失败重试复用同一键，别每次点击都换新键。

### 10. 前端状态机怎么设计流式卡片？
分 idle、connecting、streaming、waiting、completed、failed、cancelled 等，并定义允许转移。终态不再被旧进度改回运行中，交互等待不等于完成；事件按版本/序号处理，异常可恢复。

### 11. ★ 服务端只读权限变化怎么同步 UI？
接口返回当前能力，前端隐藏/禁用编辑并处理 403/404/409 等结果，缓存按资源和身份失效。UI 只负责提示，真正操作时后端仍需重新授权；不能靠页面首次加载的 readonly 永久放行。

### 12. 流式 Markdown 为什么会破坏布局？
未闭合代码围栏、长行、表格和重复全量解析导致抖动。做增量分段与尺寸约束，稳定已完成段落；HTML/链接按安全规则处理。不要为了实时感每个字符都重新挂载整篇文档。

### 13. 内存持续上涨怎么查？
看 heap snapshot 的保留路径，找未清理的 listener/reader/observer、无上限日志和历史缓存。重复进入退出页面观察是否回落；正常峰值与长期增长分开，不能只看一次任务的最高点。

### 14. ★ React 并发渲染会自动并行跑 JS 吗？
不会把普通组件代码分到多个线程。React 可调度、暂停和放弃部分渲染工作，要求渲染保持纯；昂贵 CPU 任务仍需减少、分片或放 Web Worker，startTransition 不能让重循环消失。

### 15. startTransition 适合流式文本吗？
可把非紧急更新标记为可被打断，但输入值本身应保持及时。先合并事件、缩小更新范围，再评估 transition；它不保证每个中间状态都提交，也不能代替消息持久化与终态处理。

### 16. optimistic UI 与服务器结果冲突怎么办？
按 mutation ID 和服务器版本合并，返回冲突时展示用户修改与当前值。不要直接回滚整个列表；已完成的其他 mutation 必须保留。多端编辑需要后端并发控制，前端只做可理解的冲突反馈。

### 17. ★ 动态高度聊天列表怎么保持滚动位置？
根据是否接近底部决定自动跟随，用户上翻时保持锚点；图片和代码块尺寸变化要修正测量。历史向上插入前后用稳定元素位置补偿，不能每次新 token 都强制滚到底。

### 18. reducer 收到乱序终态事件怎么办？
事件附带运行版本和递增序号，旧版本丢弃，同版本只接受有效前进；终态补充字段可有专门规则。协议没有序号时先定义可判定边界，不能仅用浏览器本地到达时间当业务顺序。

### 19. 怎么验证性能优化没有改坏行为？
固定长对话、快速切换、断线重放和取消场景，比较提交数、长任务、输入延迟与内存；同时断言完整文本、终态和归属正确。只测渲染次数下降可能掩盖漏事件。

### 20. ★ 项目里可讲哪一个 React 优化点？（项目）
可以结合源码分层和 selector 粒度，解释为什么流式更新不能让整片工作区订阅。具体收益需要 Profiler/性能记录；没量过就讲改法和验证指标，不能把 AGENTS.md 的规则说成已经获得某个倍数提升。

# 第二部分：Next.js

## Next.js 入门（20 题）

### 1. ★ Next.js 与 React 什么关系？
React 是 UI 库，Next 是基于它的应用框架，提供路由、服务端渲染、构建与服务端能力。使用 Next 不等于所有页面都 SSR，也不表示业务后端必须迁进 Next。

### 2. App Router 的 page 和 layout 是什么？
page 是路由页面，layout 提供嵌套共享结构，切换子路由时可保留其状态。路由由目录组织；别把需要每次重置的表单状态不加考虑地放在长期保留的 layout 中。

### 3. ★ Server Component 和 Client Component 怎么分？
服务端组件适合读服务端数据并减少浏览器 JS；客户端组件用于 state、Effect、事件和浏览器 API。客户端边界通过 'use client' 声明，向客户端传递的数据必须符合 React 支持的序列化协议。

### 4. 'use client' 是否表示完全不在服务端执行？
不是。客户端组件初次加载仍可能参与服务端 HTML 预渲染，再在浏览器水合。不能在渲染时无条件访问 window/localStorage；浏览器专属行为放合适生命周期或明确禁用该组件 SSR。

### 5. ★ SSR、SSG、CSR 有什么区别？
SSR 按请求生成 HTML，SSG 在构建或再生成阶段产出，CSR 主要在浏览器获取数据渲染。实际页面可混用；选择取决于个性化、更新频率、首屏与部署限制，不只看 SEO。

### 6. 水合是什么？
浏览器把交互能力接到服务端生成的 HTML 上。服务端和客户端首次渲染应一致；随机数、本地时间、浏览器状态和不同数据版本都可能引起 mismatch。

### 7. ★ Link 和普通 a 有什么区别？
Link 支持框架的客户端导航与预取等行为，普通 a 导航通常刷新整个文档。外部下载/跨站链接按需求使用；预取会带来资源成本，敏感操作不能通过访问一个预取链接就触发。

### 8. 动态路由怎么组织？
用 [id] 表示动态段，[...slug] 表示多段捕获，可选捕获有对应语法。params 在较新版本按异步请求 API 使用；仍要校验格式、权限和资源是否存在，路径名不是身份凭证。

### 9. loading.tsx 的作用？
给路由段提供加载边界，等待内容时展示占位。它改善等待体验，不会减少慢查询本身耗时；合理拆边界，别让一个全页 loading 遮住已经可交互的静态结构。

### 10. ★ error.tsx 与 not-found 有什么区别？
error 处理路由段的运行失败并提供恢复 UI；not-found 表示资源或路由不存在。它们对应不同产品语义；权限隐藏资源时按后端约定展示不存在，不把所有接口错误都当 404。

### 11. Route Handler 是什么？
在 route.ts 等文件中定义 HTTP 方法处理，可做 BFF、回调或轻量服务。它是服务端入口，需要校验身份、输入和请求体大小；不能因为和页面同仓库就省略接口安全控制。

### 12. ★ rewrite 和 redirect 区别？
rewrite 在服务端内部改请求目标，浏览器地址通常保持原样；redirect 让客户端跳转到新 URL。rewrite 适合接口代理，redirect 适合页面迁移；代理后仍需正确传递 cookie 和状态码。

### 13. 项目怎样代理后端？（项目）
frontend 的 next.config.ts 配置多条 API rewrite；console/gateway 只有设置各自代理目标变量时才启用。部署可能由同域网关转发，不能说浏览器的每个 /api 请求必经 Next。

### 14. 环境变量哪些能放客户端？
只有明确允许公开的配置才能暴露；NEXT_PUBLIC_ 常在构建时替换进浏览器包，不能放密钥。非公开变量应留服务端，但服务端读取后再返回给客户端照样会泄露。

### 15. ★ cookies 和 headers 怎么读取？
使用框架提供的请求 API；Next 15 引入异步形式，迁移应使用 await 等正确方式，16 移除多项同步兼容。读取用户信息后要考虑路由动态行为及缓存，避免复用其他用户的数据。

### 16. Next 的 fetch 默认都缓存吗？
不能这样说，默认行为随版本变化。Next 15 已改变 fetch、GET Route Handler 等默认缓存策略；需要缓存时显式表达并检查路由配置，复习时不要背旧版「一律 force-cache」。

### 17. 图片组件解决什么问题？
提供图片尺寸、懒加载和优化相关能力，帮助减少布局位移与传输成本。远端图片来源要限制，宽高/布局要合理；动态鉴权图片和静态导出有额外部署约束。

### 18. ★ metadata 是做什么的？
管理页面标题、描述与分享信息，可静态声明或按路由生成。服务端生成时避免把私有文档摘要放进公开 metadata；SEO 信息也需要遵循资源权限。

### 19. standalone 输出有什么用？（项目）
追踪所需运行文件，生成更易打包部署的服务目录；console/gateway 使用它。静态资源、public 与运行环境仍要正确打包配置，standalone 不等于单个无依赖可执行文件。

### 20. Next 15 和 Next 16 为什么要分开回答？（项目）
三个前端并非同一个大版本。升级涉及缓存、请求 API、工具链和命名变化，Next 16 也移除了 next lint。以各仓库 package.json 与升级说明为准，不能复制一份命令就保证全部可用。

## Next.js 中等（20 题）

### 1. ★ 哪些组件应该放客户端边界？
把交互小岛尽量放在需要 state/事件的最小子树，静态结构和敏感数据读取保留服务端。'use client' 会影响导入链，不能为解决一个 window 报错就把整棵应用改成客户端。

### 2. 服务端组件能把服务端组件传给客户端吗？
可由服务端父组件把已经构建的服务端内容作为 children 等传给客户端组件组合。客户端模块直接导入含服务端依赖的模块是另一回事；按边界组合，别把数据库代码带进浏览器导入链。

### 3. ★ RSC 和 SSR 为什么不等价？
SSR 产生 HTML，RSC 描述服务端组件树并参与客户端导航更新；客户端组件也能被 SSR。两者可合作，分析性能时分别看 HTML、RSC payload 和 JS，而不是把 RSC 简称成一种模板引擎。

### 4. 请求内去重和持久缓存有什么区别？
请求内去重减少一次渲染内重复读取；持久缓存会跨请求复用并需失效规则。范围、适用 API 和运行环境可能不同，不能认为 fetch 调两次没访问网络就证明它被跨用户缓存。

### 5. ★ Next 缓存有哪些层次？
可从请求内去重、数据缓存、路由输出与客户端路由缓存理解，但具体默认和 API 随版本/配置变化。分别写清谁缓存、缓存键、有效期和失效条件，避免把所有问题都归因于浏览器缓存。

### 6. revalidatePath 和 revalidateTag 怎么选？
前者按路径更新关联内容，后者按数据标签管理相关缓存。何时立即失效、何时延迟再验证要看版本和调用上下文；权限敏感数据不能靠长缓存加偶尔失效保障即时撤权。

### 7. ★ 动态数据怎么避免跨用户缓存？
从可信请求获取身份，明确禁用不合适的共享缓存，或把授权范围与数据版本纳入缓存键。读取后最小化传给客户端的字段；不能把全局变量当请求上下文。

### 8. Server Action 是普通内部函数吗？
不是，它会形成可从客户端触发的服务端入口。每次执行仍需鉴权、校验参数、检查资源权限和幂等；函数在服务端定义不表示调用者参数可信，错误输出也不能暴露密钥。

### 9. ★ 为什么 Server Component 不应该绕 HTTP 请求自己的 Route Handler？
同一服务端可以直接调用共享数据层，少一次网络并避免构建期服务尚未监听的问题。对外协议或独立服务仍可走 HTTP；共享层保留授权，别因「内部调用」省掉权限验证。

### 10. 怎么避免数据请求瀑布？
无依赖的请求尽早并行，需要前置结果的再串行；按边界流式展示慢内容。先辨认真实依赖，不能盲目 Promise.all 导致未授权的数据请求也发出；失败策略按独立模块设计。

### 11. loading、Suspense 和流式 SSR 如何协作？
Suspense 划分可渐进交付的区域，loading 是路由层的方便约定。服务器可以先发送外壳再补内容；代理缓冲、压缩和客户端水合仍会影响首屏实际时间，需从浏览器观察。

### 12. ★ BFF 层做什么，不做什么？
聚合接口、转换前端所需字段、管理安全的会话访问，减少浏览器复杂度。避免把核心规则复制成另一份后端真相；如果项目主要用 rewrite，就不要把它包装成已经实现复杂聚合 BFF。

### 13. cookie 经过 rewrite 有什么坑？
域、路径、SameSite、Secure、代理协议与 Set-Cookie 传递都可能影响登录。逐跳查看请求/响应头，校验主机与路径；同域代理减少跨域问题，但不会自动修复 CSRF 与错误 cookie 配置。

### 14. 如何集成第三方客户端组件？
为需要浏览器 API 的库设置恰当客户端边界，必要时按框架能力动态加载。避免服务端导入阶段就访问 window；同时考虑首屏占位、样式插入和包体积，别直接禁掉整页 SSR。

### 15. ★ antd 的服务端样式要注意什么？
按其与当前 Next/React 版本的集成方式收集并插入样式，防止首屏闪烁和重复样式。项目依赖中有 nextjs registry 与 React 19 兼容补丁；实际接入仍需看 Provider，不凭包名就说全部配置正确。

### 16. 路由组、平行路由、拦截路由分别用在哪？
路由组组织目录而不改变 URL；平行路由展示多个插槽；拦截路由可在当前上下文中呈现目标页面。复杂路由要覆盖直达、刷新和回退，别只验证从某个按钮点开时正常。

### 17. ★ 静态导出能代理后端吗？
纯静态文件没有 Next 服务进程，不能执行运行时 rewrite、服务端函数等。API 代理应由实际部署网关承担，或选择保留服务端运行方式；不能把 standalone 与静态导出混为一谈。

### 18. 怎么减少客户端 bundle？
分析依赖体积，缩小 use client 边界，按需加载重编辑器/图表，避免大 barrel 牵进无关依赖。看实际构建结果与首屏交互，而不只计算源码行数。

### 19. middleware / proxy 能承担全部鉴权吗？
可做快速路由判断，但受运行环境和匹配规则约束，真正的数据入口仍需授权。Next 16 的 proxy 命名迁移需按版本处理；不能把页面重定向当作 API 已安全。

### 20. ★ 怎么测试 Next 页面？
纯逻辑与交互用单测，路由、cookie、SSR/水合、代理和重连用本机集成/E2E。项目默认开发命令可能指向共享后端，应选择明确的本地入口，不能为验证前端文档触发共享数据写入。

## Next.js 高难（20 题）

### 1. ★ 水合只在部分用户机器报错？
比较服务端与客户端首屏数据、时区、语言、随机值、浏览器扩展和无效 HTML 嵌套。构建可复现样本定位差异；suppressHydrationWarning 只适合少数已知差异，不能用来掩盖整页错配。

### 2. 页面显示了上一个用户的数据怎么查？
立即检查共享缓存、模块级状态、CDN cache key 与登录切换后的客户端缓存。以身份和资源版本重建边界，敏感接口服务端复核；只在登出时清空 Redux 无法修复服务端缓存泄露。

### 3. ★ rewrite 后 SSE 总是攒一大段才输出？
逐跳测试直接后端、Next 代理、外层代理到浏览器的事件间隔。检查缓冲、压缩和超时，确认代码未先 await response.text()。保留最小流式样本，不能只根据普通 API 延迟判断。

### 4. Next 服务端内存持续增长怎么定位？
分请求峰值、全局缓存、未关闭流、图片优化及第三方库泄漏。用固定负载观察 GC 后基线与堆保留路径，限制无界缓存；单纯增加 Node heap 会推迟 OOM，不等于修复。

### 5. ★ 多副本缓存不一致怎么处理？
先明确哪些缓存进程内、哪些共享，统一版本和失效事件；必要时使用部署支持的共享缓存机制。私有内容仍要即时授权，不能靠让请求固定在同一副本解决权限变化。

### 6. 发版后浏览器加载旧 chunk 导致白屏？（项目）
核对 HTML/JS 版本组合、CDN 与 Service Worker。项目使用 Serwist，旧 SW 可能缓存旧资源；采用兼容的发布/资源保留与更新提示，在本机清理 SW 验证，不把永久禁用缓存当最终方案。

### 7. Server Action 重复执行会怎样？
网络重试和用户重复提交都可能触发，因此业务幂等仍必需。操作 ID 与唯一约束防重复，提交状态与重试分开；对支付、审批等不能只依赖 pending 按钮状态。

### 8. ★ 缓存失效触发大量回源怎么办？
把缓存条目分散过期，合并相同请求，给回源限并发，按允许程度使用陈旧数据再验证。权限变化类不能随意 stale；缓存恢复期间也要保护数据库，防止重试叠加。

### 9. 读取用户 cookie 后整页变慢怎么优化？
确认动态数据实际影响哪些组件，分开公共缓存内容与私有读取，避免根 layout 无差别阻塞全页。按部署支持选择边界缓存与流式策略；不能为了缓存绕过身份读取。

### 10. ★ Next 15 升 16 最容易漏什么？
检查异步请求 API 的同步兼容移除、工具链/配置变化、next lint 移除、middleware/proxy 迁移及缓存行为。先按官方清单逐项校验，再本机验证代理、样式、水合与构建产物，不只升级 package.json。

### 11. 本地能登录，部署后 cookie 丢了？
对照实际 HTTPS、代理头、cookie Domain/Path/Secure/SameSite 和多层转发。确认服务认为的外部协议是否正确；不要用取消 Secure 或把所有域都放开来绕过根因。

### 12. SSR 访问内部地址为什么有风险？
若目标 URL 受用户控制，服务器可被用来访问内网或云元数据，形成 SSRF。使用目标白名单、协议限制、解析后地址校验与跳转约束；rewrite 也不能开放成任意代理。

### 13. ★ 页面快了但服务器成本翻倍？
检查预取、服务端重复请求、缓存未命中、长连接驻留和渲染 CPU。按实际导航率估预取收益，合并重复读取并测每请求成本；不能只优化浏览器首屏而忽略后端负载。

### 14. 并行 Route 请求产生不一致快照？
相互独立的数据可并行，必须一致的业务读取需服务端聚合事务或版本水位。客户端把两次不同时刻结果拼起来，不自动获得一致快照；返回版本帮助识别过时内容。

### 15. 冷启动影响首字怎么办？
拆依赖初始化、连接建立和实际模型时间，避免所有角色加载重库。给就绪探测留合理启动期，按需/预热选择有成本依据；项目已有 APP_SCOPE，不能让 console 入口引入整套 AI 依赖。

### 16. ★ 怎样避免错误页面泄露内部信息？
客户端展示可行动的错误和关联 ID，服务端记录受控详情，过滤异常里的 SQL、URL 凭证与 prompt。错误边界只负责展示，不等于已完成日志脱敏；失败重试仍要验证授权。

### 17. 构建期变量与运行变量不一致怎么查？
查哪些值进入编译产物、哪些在服务进程启动后读，尤其 NEXT_PUBLIC_ 与 next.config 生成的规则。修改运行环境后重新 inspect 行为；不能假定同一镜像到处改 ENV 就改了浏览器包。

### 18. 边缘运行时能用所有 Node 库吗？
不能，运行时 API、原生扩展、文件系统和 TCP 能力受部署平台影响。按实际 target 验证依赖与连接方式；需要完整 Node 能力时明确选择，别因「更近用户」就把重后端逻辑迁过去。

### 19. ★ 多前端如何避免接口地址到处写？（项目）
frontend 按既定 constants/services 层管理地址与请求，console/gateway 用各自明确的代理目标配置。版本、scope 与 cookie 规则需统一约定；不要把配置分散复制到每个组件。

### 20. 面试如何说明你用 Next 的程度？（项目）
可以讲三个前端的版本、App Router、客户端状态、接口代理和 standalone。某页面实际主要 CSR 就如实讲，不能因为用了 Next 就声称深度实践了所有 RSC、Server Action 或复杂缓存能力。

# 第三部分：Node.js

## Node.js 入门（20 题）

### 1. ★ Node.js 是什么？
基于 V8 的 JavaScript 运行时，提供网络、文件、进程等服务端能力。Node 不是框架，Express 是其上的 Web 框架；浏览器 DOM API 不能直接当成 Node 内置能力。

### 2. ★ Node 是单线程吗？
普通 JS 回调主要在一个事件循环线程执行，但运行时还有系统异步 IO、libuv 线程池和可选 worker_threads。说「所有操作都单线程」不准确；CPU 重循环仍会挡住主线程。

### 3. 事件循环负责什么？
调度不同阶段的回调与任务，避免一个请求等网络时阻塞所有请求。JS 回调自身要尽快返回；异步 API 不代表回调中的 JSON 解析、正则或加密也不会阻塞。

### 4. ★ Promise 和 async/await 的关系？
async 函数返回 Promise，await 用较直观的形式组合异步步骤。await 只暂停该异步函数，不阻塞线程等待网络；但 await 后执行的重 CPU 逻辑照样会占住事件循环。

### 5. 回调、Promise、事件适合什么？
回调可表示一次完成，Promise 表示一次最终成功/失败，事件/流适合多次结果。不要把无限事件强装成一个不断 resolve 的 Promise；监听器要清理并处理 error。

### 6. ★ CommonJS 与 ESM 区别？
CommonJS 用 require/module.exports，ESM 用 import/export，加载、互操作和路径规则不同。项目 package.json 的 type 与扩展名决定解释方式；写脚本时明确 .mjs/.cjs，别混用后猜执行顺序。

### 7. package.json 与 lockfile 有什么区别？
前者声明脚本和依赖范围，锁文件记录实际解析版本与完整性。可重复安装应提交匹配的锁文件并用对应包管理器，不能只固定顶层版本却让传递依赖每次变化。

### 8. ★ dependencies 和 devDependencies 怎么分？
运行所需放 dependencies，构建/检查工具通常放 devDependencies。若部署在运行时编译或执行某工具，它也成运行依赖；多阶段镜像应把编译产物及运行所需库一起复制。

### 9. Buffer 是什么？
表示字节序列，适合文件、网络和密码学处理。字符串字符数不等于 UTF-8 字节数；接收网络分块时一个中文字符可能跨块，不能每块各自无状态地转字符串。

### 10. ★ Stream 为什么适合大文件？
逐块处理，减少一次性加载整个文件的内存。仍需处理错误、关闭和背压；把所有 chunk 先收进数组最后 concat，最终仍会占全量内存，不能算真正流式处理。

### 11. Express middleware 怎么工作？
按注册顺序处理 req/res，调用 next 交给后续，或发送响应结束。顺序决定 body 解析、认证和路由能看到什么；忘记 next 或响应可能让请求悬挂，重复响应会报 headers sent。

### 12. ★ Express 错误处理怎么写？
统一错误 middleware 接收 err、req、res、next，已发头时交给合适的后续处理。异步错误传播与 Express 大版本有关，按项目版本处理；不要把每个异常原文直接返回给客户端。

### 13. JSON body 为什么需要大小限制？
解析前请求体就可能占内存，大对象 JSON.parse 也会占 CPU。给 body、上传和解压分别设预算，超限早返回；限量不替代字段校验，合法 JSON 也可能不符合业务要求。

### 14. ★ process.env 的值是什么类型？
读取到的通常是字符串或 undefined，'false' 作为字符串仍是真值。启动时显式解析布尔、数字、URL，校验范围和必填项；不要等第一个请求才发现端口或密钥格式错误。

### 15. Node 怎么读写文件？
可用 fs/promises 做异步操作，大文件用 stream。文件路径由服务端限定根目录并规范化，防路径穿越；写入还要处理目录权限、临时文件与原子替换，不能直接信用户文件名。

### 16. ★ setTimeout(fn, 0) 是立刻执行吗？
不是，只是达到最小延迟后有资格被调度，还要等当前 JS 和相关队列。事件循环被重任务堵住时会晚很多；超时需要看实际墙钟截止时间，不能靠定时器次数算经过时间。

### 17. npm script 为什么比全局装工具好？
脚本优先使用项目依赖的可执行文件，版本随锁文件管理，团队更一致。安装脚本也会执行代码，要了解依赖来源；Node 版本和包管理器版本也应记录。

### 18. ★ Node 服务如何接收停止信号？
监听 SIGTERM/SIGINT，先停止接新流量，再等待有限时间处理在途请求，关闭连接和资源。不要在信号回调里立刻 process.exit，否则日志、响应和落库可能来不及完成。

### 19. Node 可以做 CPU 密集任务吗？
能，但不应让重任务长时间占主线程。可用 worker_threads、独立进程或后台任务服务，控制并发与内存；线程启动和数据传输有成本，小计算不必都创建 worker。

### 20. ★ 项目 Node 服务能怎么讲？（项目）
xknow-payment 用 Express 提供扫码收款页面和 API，微信通知单独读取 raw body 后验签。讲清请求解析顺序、超时和错误处理即可；它不是整个 AI Agent 后端的实现语言。

## Node.js 中等（20 题）

### 1. ★ nextTick、Promise 微任务、timer 的顺序？
都在当前同步代码之后，但 nextTick 与 Promise 的相对顺序需说明 CJS/ESM、执行上下文和 Node 版本。I/O 回调内与顶层 timer/immediate 也有差别，别背一条适用于所有情况的固定序列。

### 2. setImmediate 和 setTimeout(0) 谁先？
顶层顺序不能稳定依赖，受事件循环时点等影响；在常见 I/O 回调里 immediate 通常先进入对应 check 阶段。需要严格业务顺序应显式串联，不能把调度偶然性当同步协议。

### 3. ★ libuv 线程池处理什么？
部分文件操作、dns.lookup 和一些加密/压缩任务会用线程池，普通网络 socket 多依赖 OS 非阻塞机制。线程池饱和会拖慢看似无关操作；增大池要同时评估 CPU 与内存。

### 4. stream 背压怎么处理？
Writable.write 返回 false 表示应暂停继续写，等 drain 再继续；可优先用 pipeline 连接并传播错误。忽略背压会堆积缓冲，面对慢客户端时内存迅速增长。

### 5. ★ pipeline 比自己监听 data 有什么好处？
它统一连接流、处理背压并传播很多错误/销毁行为。仍需确认业务结束语义与 abort 支持，避免对 HTTP 响应销毁造成意外展示；特殊恢复逻辑要自己设计，不能无限重跑整个上传。

### 6. fetch 超时怎么做？
用 AbortSignal.timeout 或 AbortController，并覆盖整个需要保护的请求/读取阶段，结束后清理 timer。收到响应头不代表响应体已完整；业务还需区分取消、连接失败和结果未知。

### 7. ★ Promise.all 和 allSettled 怎么选？
all 在一个拒绝时整体拒绝，但不会自动取消其他已启动任务；allSettled 等全部完成，便于独立结果处理。无依赖请求可并行，有共享预算则加并发限制，不要一次启动十万条。

### 8. Express 4 与 5 的异步错误区别？
Express 5 会把返回 Promise 的处理器拒绝传到错误处理；Express 4 通常需显式 catch(next) 或包装器。两者都不自动捕获任意后台事件的错误；以实际依赖版本为准。

### 9. ★ 为什么支付验签要用原始 body？（项目）
签名针对原始字节/原文，先 JSON.parse 再 stringify 可能改变空白和字段顺序。项目先挂 notify 的 express.raw，再挂通用 express.json，保持验签输入；业务解析应在验签通过后进行。

### 10. 金额为什么用整数分？
避免二进制浮点的小数误差，接口明确单位并检查整数范围。乘 100 前仍要严格解析十进制输入，不能放任任意小数四舍五入；大整数要考虑 JS Number 的安全整数上限。

### 11. ★ trust proxy 是干什么的？（项目）
让框架按可信代理规则解释 X-Forwarded-*，影响客户端 IP、协议和安全判断。项目设置为 1，含义依赖部署跳数；若入口路径不同，攻击者可能伪造头，不能无条件信任所有来源。

### 12. HTTP keep-alive 如何影响性能？
复用连接减少握手，但连接池有空闲超时、最大连接数和对端关闭边界。配好请求总 deadline 与重试；遇到复用连接偶发 reset，要区分可重试读取和不可重复的写操作。

### 13. worker_threads 与 child_process 怎么选？
worker 适合同进程的并行 JS 计算，可按协议传输或共享部分内存；子进程隔离更强，可跑其他程序。两者都要有任务池、超时和回收，别每个请求无界启动一个。

### 14. ★ spawn 和 exec 的区别？
spawn 以流处理输出，exec 常经 shell 并缓存输出；不可信输入拼 shell 容易命令注入。优先明确命令与参数数组，限制输出/时间/目录和环境；shell:false 也不代替目标程序参数校验。

### 15. EventEmitter 泄漏怎么看？
监听器数量持续增长、重复响应、堆里对象无法释放是线索。once/移除 listener 要覆盖结束和错误路径；提高 maxListeners 只能调告警阈值，不能修复忘记清理。

### 16. ★ AsyncLocalStorage 有什么用？
在异步调用链传 trace_id 等请求上下文，避免全局变量串请求。第三方回调与自建异步边界需验证传播；不能把它当跨进程共享状态，worker 和外部任务要显式传关联信息。

### 17. Web Streams 和 Node Streams 有什么不同？
接口、读取方式和背压协议不同，fetch 的 body 常是 Web ReadableStream。按 API 转换并检查取消传播，别把 getReader 与 on('data') 混用；转换也不意味着丢失错误和关闭责任。

### 18. ★ 大文件哈希为什么要边读边算？
避免 readFile 把文件全放内存；流里逐块更新 hash，结束才取结果。CPU 消耗仍存在，大量并行哈希要限制并发；还要处理读错误，不能对不完整内容返回成功摘要。

### 19. 服务如何做输入校验？
对路径、query、body、header 分别校验类型、长度、枚举和业务归属；拒绝额外危险字段。JSON 解析只证明语法合法；校验完成后的数据也不能拿来绕过资源级权限检查。

### 20. ★ Node 的可观测性看什么？
请求量、错误率、延迟、事件循环延迟、堆/RSS、GC、连接池和下游耗时。排队与执行分开，日志带请求 ID；CPU 不高但延迟大也可能是线程池、外部 IO 或连接池等待。

## Node.js 高难（20 题）

### 1. ★ CPU 100%，所有请求一起变慢怎么排？
采 CPU profile 看重循环、JSON、正则、序列化或压缩，再查事件循环延迟。对大任务限输入、分片或交给 worker 池；先限流止血，不能把函数改 async 就认为 CPU 工作变异步。

### 2. CPU 不高但文件读取很慢？
检查 libuv 线程池是否被密码学/压缩占满、磁盘延迟、并发和网络文件系统。用受控样本区分排队和实际执行；提高 UV_THREADPOOL_SIZE 前评估主机核数，避免从排队变成 CPU 抢占。

### 3. ★ 服务内存增长但 heap 稳定？
看 Buffer、ArrayBuffer、原生库、线程、子进程和 RSS 碎片；堆快照只解释 JS 堆的一部分。检查流缓冲和未消费响应体，按对象/连接生命周期复现，不单纯调 V8 old space。

### 4. 大 JSON 请求怎样拖垮事件循环？
读 body 占内存，parse 和 stringify 是同步 CPU 工作，嵌套/字段量也有成本。限制字节、深度与返回量，必要时改变协议或隔离处理；不能只用异步 readFile 就消除解析阻塞。

### 5. ★ SSE 代理怎样支持慢客户端？
读取上游与写下游联动背压，限制单连接缓冲，客户端断开要取消上游。定期心跳、总/空闲超时和连接配额分别设计；别无限缓存模型输出直到用户网速恢复。

### 6. 微信支付通知来了三次怎么办？
先验签并核对金额、商户与订单，再用订单/通知业务键幂等落库，返回已处理结果。不要把通知 ID 存一个无界进程 Set 当可靠防重；进程重启和多副本都会失效。

### 7. ★ 调支付接口超时能立刻重下单吗？
超时表示结果未知，先按相同订单号查询或使用对方支持的幂等规则恢复。不能用新订单号盲重试；明确状态机、对账与恢复窗口。这是设计原则，不据此断言项目已实现完整对账系统。

### 8. Node 优雅停机怎样覆盖长连接？
先 readiness 摘流，停止接受新连接，跟踪 HTTP/SSE/WebSocket 与后台工作；有限期结束后主动关闭残留并记录未完成业务。具体 close API 行为随 Node 版本变化，验证真实连接而非只测空闲服务。

### 9. ★ 服务发了响应，异步处理却失败怎么补偿？
如果工作必须可靠，响应前先持久化业务意图，再由队列/outbox 执行；后台 Promise 不能保证进程重启后继续。日志能帮助发现失败，但不构成可靠任务存储和恢复机制。

### 10. unhandledRejection 能捕获后继续运行吗？
先修复缺失的错误链路，按 Node 版本与启动策略处理未处理拒绝。uncaughtException 后进程状态可能不可信，通常记录并由监管重启；全局吞异常长期运行会掩盖部分写入和资源泄漏。

### 11. 正则为什么可能导致拒绝服务？
有些模式对恶意输入出现灾难性回溯，占住事件循环。限制长度、改写模式或用合适的线性匹配工具，复杂校验设资源边界；「只是匹配一个字符串」也可能是昂贵计算。

### 12. ★ 多进程全局限流怎么做？
进程内 Map 只能管本进程，跨实例用原子共享存储或统一入口。定义用户/组织/接口维度、突发额度和故障策略；计数与过期要原子，客户端 IP 还需可信代理规则。

### 13. 为什么不能无界 Promise.all 访问数据库？
所有任务立即启动，连接池排队、内存和下游 QPS 同时增长。用并发池、分批与取消预算，记录排队时间；请求超时后未取消的任务仍可能执行，要控制副作用和资源回收。

### 14. 线程池任务结果如何防串单？
每个任务有唯一 ID、输入版本和目标身份，worker 回包先匹配，超时/取消后的旧结果不能更新新任务。协议覆盖崩溃与重启，池限制在途数量；共享可变内存要有同步机制。

### 15. ★ Node 服务如何避免 SSRF？
外部 URL 限协议、域名/端口和跳转，解析后校验私网/本地/元数据地址并处理 DNS 重绑定风险。不要把任意 fetch 封成公共接口；请求预算、响应大小和凭证转发也要限制。

### 16. 上传接口如何防目录穿越与解压炸弹？
使用服务端生成的文件名和受控目录，校验规范化/符号链接后的目标；限制总解压大小、文件数、嵌套和时间。原始压缩包小不表示解压成本小，失败要清理临时产物。

### 17. 金额计算超过 Number 安全范围怎么办？
用 BigInt 或可靠十进制库，接口明确字符串/整数单位与舍入规则。BigInt 不能直接默认 JSON.stringify，序列化协议需双方约定；禁止在中途转回 Number 重新引入精度损失。

### 18. ★ 如何做依赖供应链的基本控制？
固定运行时和锁文件，用可重复安装，审查新增依赖与安装脚本，保持漏洞修复和构建可追溯。扫描结果需按实际可达代码评估，避免盲升破坏协议；密钥不进入包、镜像层或日志。

### 19. 如何验证 Node 的事件循环理解？
分别在明确 CJS、ESM、I/O 回调内写小实验，打印同步、微任务、nextTick、timer 和 immediate。断言有保证的先后关系，不断言顶层 timer/immediate 的偶然顺序；本篇附自检脚本。

### 20. ★ 全栈面试如何讲 Node 项目边界？（项目）
讲收款服务的 Express 路由、raw body 验签、整数金额和外部请求超时；Agent 主后端仍是 Python。关于持久化幂等、多副本和对账，先查实际实现，缺失就作为改进方案，不说已经上线。
